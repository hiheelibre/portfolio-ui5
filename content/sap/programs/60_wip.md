## 문제 정의 및 개발 배경
생산오더에 원자재비와 가공비가 투입되었어도 월말까지 생산이 끝나지 않았다면, 그 비용은 재공품으로 평가해 자산으로 잡아야 합니다.

태산자전거 프로젝트에서는 실제 임률 산정과 가공비 배부 이후에도 REL(생산중) 상태로 남아 있는 생산오더를 WIP 산정 대상으로 정했습니다. 매월 재공품 금액 전액을 새로 전기하면 이미 잡힌 잔액이 중복 반영될 수 있으므로, 전월 WIP와 당월 WIP의 차이만 전기하도록 설계했습니다.

### 앞 단계와의 구분
| 구분 | 처리 프로그램 | 대상 오더 |
| --- | --- | --- |
| 가공비 배부와 오더 마감(TEC 전환) | 실제 임률 산정 및 생산오더 가공비 배부(SAPMZC1CO0002) | GRD 오더 중 조건을 갖춘 오더만 TEC |
| 재공품 산정과 증분 전기 | 이 프로그램(SAPMZC1CO0005) | REL 오더 (오더 상태는 바꾸지 않음) |

## 업무 프로세스 및 데이터 흐름
REL 오더 조회 → 투입원가 집계 → 전월 WIP 조회 → 당월 WIP와 증분 계산 → 오더별 상태 판정 → 결과 저장 → 전표 Preview와 검증 → WIP 전기 → 결과 반영 순서로 진행됩니다.

### WIP 계산
당월 WIP = 오더 차변 투입원가 - 오더 대변 입고액

전기 대상 금액(당월 정산금액) = 당월 WIP - 전월 WIP

| 증감 | 차변 | 대변 |
| --- | --- | --- |
| WIP 증가 | 131000 재공품 (전기키 40) | 931000 생산오더정산 (전기키 50) |
| WIP 감소 | 931000 생산오더정산 (전기키 40) | 131000 재공품 (전기키 50) |

### 주요 데이터
| 데이터 | 테이블 | 용도 |
| --- | --- | --- |
| 오더 귀속 원가 | ZTC1CO0001 | 결산월 오더별 투입원가와 입고액(계정 132000) 집계, 가공비 배부 계정(940000~942000) 존재로 배부 완료 판단 |
| 생산오더 | ZTC1PP0009 / ZTC1PP0010 | REL 상태, 생산기간, 오더와 입고 수량 |
| WIP 결과 | ZTC1CO0042 | 당월 산정 결과와 전기 상태(P), 전표번호. 다음 달의 전월 WIP 원천 |
| WIP 전표 (CBO) | ZTC1FI0006 / ZTC1FI0007 / ZTC1CO0001 | FI 헤더, FI 라인, CO 전표 |

전월 WIP는 ZTC1CO0042의 이전 결산월 결과에서 읽고, 결산월이 1월이면 전년도 12월을 참조합니다.

## 핵심 ABAP 구현
### A. Delta 기반 WIP 산정
오더별로 원가를 집계할 때 입고 계정(132000)은 절대값으로 대변 입고액에, 나머지는 차변 투입원가에 더합니다. 이미 전기된 WIP 전표는 집계에서 제외하고, 전월 WIP를 매핑해 당월 WIP와 전기 대상 금액을 계산합니다.

```abap
lv_poper_i = gs_input-poper.
lv_gjahr_i = gs_input-gjahr.

IF lv_poper_i = 1.
  lv_gjahr_i = lv_gjahr_i - 1.
  lv_poper_i = 12.
ELSE.
  lv_poper_i = lv_poper_i - 1.
ENDIF.

lv_prev_gjahr = lv_gjahr_i.
lv_prev_poper = lv_poper_i.
```

```abap
gs_wip-wip_amt  = gs_wip-debit_amt - gs_wip-credit_amt.
gs_wip-post_amt = gs_wip-wip_amt - gs_wip-prev_wip_amt.
```

산정 결과는 ZTC1CO0042에 MODIFY로 저장하되, 이미 전기된(P) 오더는 저장 대상에서 빼고 화면에도 DB에 저장된 값을 그대로 보여 줍니다.

### B. 오더별 상태 판정 (set_wip_status)
| 순서 | 상태 | 조건 | 표시 |
| --- | --- | --- | --- |
| 1 | 완료 | ZTC1CO0042에 이미 전기(P)된 오더 | 녹색, 이미 WIP 정산 완료 |
| 2 | 확인 | 가공비 배부 계정 원가가 없는 오더 | 노란색, 가공비 배부 미완료 |
| 3 | 오류 | 당월 WIP가 음수인 오더 | 빨간색, 입고액 또는 투입원가 확인 필요 |
| 4 | 제외 | 당월 정산금액이 0인 오더 | 회색, 당월 정산금액 0 |
| 5 | 대상 | 위 조건에 해당하지 않는 정상 오더 | 녹색, WIP 산정 대상 |

### C. 전표 Preview와 차대변 균형 검증
전기 전에 산정 완료 여부를 확인하고, Preview 라인을 오더별로 검증합니다.

- 계정, 전기키, 통화 누락과 금액 0 이하 확인
- 전기키는 40과 50만 허용, 오더당 라인이 차변 1개와 대변 1개인지 확인
- 오더별 차변과 대변 금액, Preview 전체 차변과 대변 합계가 같은지 확인

### D. 오더 단위 전기와 보상 처리
대상 오더를 하나씩 처리하며, 먼저 ZTC1CO0042에서 해당 오더의 전기 여부를 다시 확인합니다. 전표번호는 공통 채번 함수 ZFC1FI0001로 받고, FI 헤더 → FI 라인 → CO 전표 순으로 만듭니다. 중간 단계가 실패하면 그 전표번호로 이미 만든 데이터를 삭제하고, 해당 오더만 오류로 기록한 뒤 다음 오더를 계속 처리합니다.

```abap
PERFORM insert_fi_header USING    lv_belnr
                         CHANGING pv_msgty
                                  pv_msgtx.
IF pv_msgty = 'E'.
  PERFORM delete_created_document USING lv_belnr.
  EXIT.
ENDIF.

PERFORM insert_fi_segment USING    lv_belnr
                          CHANGING pv_msgty
                                   pv_msgtx.
IF pv_msgty = 'E'.
  PERFORM delete_created_document USING lv_belnr.
  EXIT.
ENDIF.

PERFORM insert_co_document USING    lv_belnr
                           CHANGING pv_msgty
                                    pv_msgtx.
IF pv_msgty = 'E'.
  PERFORM delete_created_document USING lv_belnr.
  EXIT.
ENDIF.
```

성공한 오더는 ZTC1CO0042에 전기 상태 P와 전표번호를 기록하고, 모든 오더를 처리한 뒤 COMMIT합니다.

### E. HTML 대시보드와 ALV 연동
- HTML 대시보드: REL 오더 수, 가공비 배부 완료 수, WIP 산정 대상 수, 오류와 확인 필요 수, 총 WIP 정산금액
- 오더별 WIP ALV에서 생산오더를 누르면(hotspot) 오른쪽 HTML 패널에 오더 상세와 WIP 계산식, 아래 ALV에 원가 구성 상세를 표시
- 오더별 WIP, 원가 구성 상세, 전표 Preview ALV는 Field Catalog를 각각 두고, 상태별 셀 색으로 구분

## 설계 판단 및 트러블슈팅
대표 사례 두 가지와 보조 사례 두 가지입니다.

### 사례 1. 재실행 시 WIP 이중 전기 위험
- 문제: 같은 결산월에 프로그램을 다시 실행하면 이미 전기한 오더가 다시 대상으로 잡혀 재공품이 이중으로 계상될 수 있고, 화면 플래그만으로는 세션이 바뀌면 상태를 알 수 없음
- 처리: 전기 직전에 오더별로 ZTC1CO0042의 전기 상태(WIP_STATUS = P)를 DB에서 다시 조회하고, 이미 전기된 오더는 새 전표를 만들지 않고 기존 전표번호로 화면 상태만 맞춤
- 처리: 재산정 때도 전기 완료 오더는 저장 대상에서 빼고 DB 값을 그대로 표시하며, 원가 집계에서도 이미 전기된 WIP 전표를 제외

```abap
SELECT SINGLE belnr
  FROM ztc1co0042
  WHERE bukrs      = @gs_input-bukrs
    AND gjahr      = @gs_input-gjahr
    AND poper      = @gs_input-poper
    AND aufnr      = @pv_aufnr
    AND wip_status = 'P'
  INTO @pv_belnr.

IF sy-subrc = 0 AND pv_belnr IS NOT INITIAL.
  pv_exist = 'X'.
ENDIF.
```

### 사례 2. 전표 생성 중 일부 데이터만 저장되는 문제
- 문제: FI 헤더를 저장한 뒤 FI 라인이나 CO 전표 생성이 실패하면 일부 테이블에만 데이터가 남아 전표 간 정합성이 깨질 수 있음
- 처리: 오더별 전기를 채번 → FI 헤더 → FI 라인 → CO 전표 단계로 나누고, 단계가 실패하면 해당 전표번호로 생성한 FI 헤더, FI 라인, CO 전표를 삭제(delete_created_document)
- 처리: 실패한 오더는 오류 상태와 메시지로 남기고 다른 오더의 전기는 계속 진행. 결산 대상 전체를 한 번에 취소하지 않고 오더별 처리 결과를 구분

### 보조 사례 1. WIP 음수 오더 검증
- 입고액이 투입원가보다 커서 WIP가 음수가 되는 오더는 전기 대상에서 빼고 오류로 표시
- 가공비 배부 계정 원가가 없는 오더는 그보다 먼저 확인 상태로 분리해 선행 단계 미완료를 드러냄

### 보조 사례 2. 1월 연도 이월
- 전월을 단순히 결산월 - 1로 계산하면 1월은 기간 000이 되어 전월 WIP를 찾을 수 없음
- 결산월이 1이면 회계연도에서 1을 빼고 기간을 12로 두는 분기로 전년도 12월 WIP를 참조

- 원가 구성 상세: HTW260600001의 원재료비, 직접노무비, 제조간접비, 기계가공배부, 기계가공비 합계 1,200,000,000에서 생산입고 450,000,000을 빼면 750,000,000입니다
- 전표 Preview 금액 합계는 차변과 대변을 합쳐 6,900,000,000이며, 오더마다 같은 금액의 차변과 대변 라인이 한 쌍입니다

## 기여 및 산출물
CO 담당으로 재공품 산정과 증분 전기 기능을 개발했습니다.

### 주요 개발 영역
- REL 오더 대상 WIP 산정과 전월 대비 증분 계산
- 오더별 상태 판정과 HTML 대시보드, 상세 패널
- 전표 Preview와 차대변 검증
- 오더 단위 전기, 중복 전기 방지, 보상 처리

### 연계 업무
제조간접비 배부(SAPMZC1CO0003) → 실제 임률 산정 및 생산오더 가공비 배부(SAPMZC1CO0002) → 재공품 산정 및 전기(SAPMZC1CO0005)

### 배운 점
> 결산 프로그램은 한 번 실행하는 것이 아니라 다시 실행하고 정정하는 것을 전제로 설계해야 했습니다. 전월 결과 테이블로 잔액의 증감만 전기하고, 오더 단위로 실패를 격리하고 정리하는 구조가 반복 실행에 안전하다는 것을 배웠습니다.
