## 문제 정의 및 개발 배경
제조간접비 배부가 끝나면 생산부서 코스트센터에 비용이 모입니다. 하지만 코스트센터에 모인 비용만으로는 개별 생산오더에 가공비가 실제로 얼마나 들었는지 알 수 없습니다.

그래서 비용을 노무와 기계, 고정과 변동으로 나누고, 생산오더의 실제 활동시간으로 시간당 실제 임률을 산정했습니다. 산정한 실제 임률은 계획 임률과 비교하고, 생산오더별 가공비 배부와 전표 생성에 사용합니다.

### 실제 임률과 계획 임률의 구분
| 구분 | 실제 임률 | 계획 임률 |
| --- | --- | --- |
| 산정 시점 | 결산월마다 이 프로그램에서 산정 | 결산 전 계획 단계 |
| 계산 근거 | 결산월 발생 비용 ÷ 실제 활동시간 | 계획 단계의 단가 |
| ZTC1CO0032 위치 | 버전 000, 기간 = 결산월 (이 프로그램이 저장) | 버전 001, 기간 = 결산월 (이 프로그램은 비교용으로 읽기만 함) |

## 업무 프로세스 및 데이터 흐름
제조간접비 배부 결과 → 비용성격 분류 → 생산실적과 공수 조회 → 실제 임률 산정 → 계획 대비 비교 → 생산오더별 가공비 배부 → 전표 미리보기와 전기 → 상태별 후속 처리 순서로 진행됩니다.

### 처리 순서
| 순서 | 수행 내용 | 처리 기준 |
| --- | --- | --- |
| 1 | 조회와 대상 확인 | 결산월 생산오더 현황과 가공비 산출 대상 비용 전표(CO 전표 ZTC1CO0001, 배부 이력 ZTC1CO0038) 조회 |
| 2 | 비용성격 분류 | 비용 전표를 노무고정, 노무변동, 기계고정, 기계변동으로 구분 |
| 3 | 생산실적과 공수 집계 | 생산실적(ZTC1PP0012)의 실제 노무시간, 기계시간(분)을 코스트센터, 활동유형별로 합산 |
| 4 | 실제 임률 산정 | 고정 임률 = 고정비 ÷ 실제 시간, 변동 임률 = 변동비 ÷ 실제 시간, 실제 임률 = 두 값의 합 |
| 5 | 계획 대비 비교와 저장 | 계획 단가와의 차이 표시. 테스트 실행이 아니면 실제 임률을 ZTC1CO0032 버전 000, 결산월 기간으로 저장 |
| 6 | 생산오더 가공비 배부 | 오더별 활동시간(시간) × 실제 임률 ÷ 가격단위 |
| 7 | 전표 미리보기와 전기 | Header, 차변, 대변을 미리 보고 전기. 생산오더 차변, 코스트센터 대변의 CBO 전표 생성 |
| 8 | 상태별 후속 처리 | REL은 WIP 대상 유지, GRD는 조건 충족 시 TEC 전환, 처리 결과 팝업과 담당자 메일 통보 |

### 활동시간 기준
| 활동유형 | 사용하는 시간 | 생산실적 필드 |
| --- | --- | --- |
| 노무(코드 끝 H, 예: WELDSH) | 실제 노무시간(분) | ISMNB |
| 기계(코드 끝 M, 예: WELDSM) | 실제 기계시간(분) | ISMNE |

분 단위 시간은 60으로 나눠 시간으로 환산합니다. 실제 시간이 없는 조합은 임률을 산출하지 않고 오류 목록으로 따로 보여 줍니다.

### 후속 처리 범위
REL 오더는 생산 중인 오더로 가공비 배부 후에도 재공품(WIP) 대상으로 남습니다. 이 프로그램은 WIP 대상 표시와 다음 결산 단계(STEP 3 WIP 계산)로의 연결까지 담당하며, 재공품 금액 계산과 전기는 별도의 WIP 프로그램에서 처리합니다.

## 핵심 ABAP 구현
### A. 비용성격별 집계와 실제 임률 계산
비용 전표를 코스트센터별로 읽으면서 노무 활동유형(H)은 노무고정(LF), 노무변동(LV) 비용을, 기계 활동유형(M)은 기계고정(MF), 기계변동(MV) 비용을 합산합니다. 활동유형에 맞는 실제 시간을 분에서 시간으로 바꾼 뒤 고정 임률과 변동 임률을 각각 구합니다. 실제 시간이 0이면 임률을 비우고 사유를 표시합니다.

```abap
IF ls_lstar-lstar CP '*H'.
  lv_time_min = ls_time-ismnb.
ELSEIF ls_lstar-lstar CP '*M'.
  lv_time_min = ls_time-ismne.
ELSE.
  lv_time_min = ls_time-ismne + ls_time-ismnb.
ENDIF.

lv_time_h = lv_time_min / 60.
gs_detail-tot_time = lv_time_h.

IF gs_detail-tot_time IS INITIAL.
  gs_detail-icon  = icon_led_red.
  gs_detail-bigo  = '생산실적 시간이 없어 임률 산출 불가'.
  CLEAR: gs_detail-fprice,
         gs_detail-vprice,
         gs_detail-price.
ELSE.
  gs_detail-fprice = gs_detail-fcost / gs_detail-tot_time.
  gs_detail-vprice = gs_detail-vcost / gs_detail-tot_time.
  gs_detail-price  = gs_detail-fprice + gs_detail-vprice.
```

### B. 생산오더별 가공비 배부
오더, 공정, 활동유형별 실제 시간을 시간 단위로 바꾸고, 같은 코스트센터와 활동유형의 실제 임률과 가격단위를 적용해 배부 금액을 계산합니다. 임률이 없거나 금액이 0인 행은 배부 상태 문구로 구분하고, 이미 배부 전표가 있는 오더는 배부완료로 표시합니다.

```abap
lv_time_h = lv_time_min / lv_unit.   " lv_unit = 60

gs_alloc_post-amount = lv_time_h * gs_alloc_post-price / lv_price_unit.
```

### C. Module Pool 단계형 화면
메인 화면 0100의 Tabstrip에 세 업무 탭을 Subscreen으로 두었습니다.

- 0101 조회 / 대상 확인: 생산오더 현황과 비용 전표 (비용성격별 필터 버튼)
- 0102 가공비 산출 결과: 실제 임률 산출과 계획 단가 비교
- 0103 오더 가공비 배부 및 처리결과: 오더별 배부와 활동유형별 상세
- 팝업 화면: 0110 테스트 실행 저장 예정 데이터, 0130 전표 미리보기, 0150 전기 처리 결과, 0120 메일 통보, 0140 오더 원가센터 상세

탭으로 이동할 때는 rebuild_data_for_stage가 그 단계에 필요한 데이터만 다시 구성합니다(TAB1 오더와 비용 전표, TAB2 여기에 임률 산출과 오류 목록, TAB3 여기에 배부 데이터).

### D. ALV Field Catalog 분리
생산오더, 비용 전표, 임률 산출, 오류, 배부 ALV와 전표 미리보기, 전기 결과 ALV는 각자의 Field Catalog를 따로 만듭니다. 전표 미리보기용(build_post_preview_fcat)과 전기 결과용(build_post_result_fcat)을 분리하고, 출력 데이터 기준으로 Field Catalog를 정리하는 공통 루틴(optimize_fcat_by_data)을 두었습니다.

### E. HTML Viewer와 SAPEVENT
왼쪽 검색조건과 처리 버튼, 결산 진행 상태(1 대상 오더 확인 ~ 5 TEC 전환, 진행률)는 HTML로 그려 HTML Viewer에 표시합니다. 버튼은 SAPEVENT로 조회, 임률 산출, 저장, 탭 이동, 배부, 초기화 동작을 프로그램에 전달합니다.

### F. DB 기준 결산 단계 복원
화면 단계를 전역변수만으로 관리하지 않고, 결산 단계 테이블(ZTC1CO0036)의 STEP 31~35 완료 이력과 결산월의 실제 배부 전표(전표유형 CO, 생산오더 지정) 존재 여부를 조회해 현재 단계와 표시할 버튼을 정합니다.

```abap
*--------------------------------------------------------------------*
* HTML 화면 모드 복원
* - TEC 완료 전이라도 배부 전표가 있으면 A 상태로 표시
* - 단, 현재 세션에서 임률 산출 결과 GT_DETAIL이 존재하면
*   저장 전 단계(C)를 유지해야 저장 버튼이 표시됨
*--------------------------------------------------------------------*
IF gv_p35_done = abap_true.
  gv_html_mode = 'F'.
ELSEIF gv_p34_done = abap_true
    OR lv_alloc_found = abap_true.
  gv_html_mode = 'A'.
ELSEIF gv_p33_done = abap_true.
  gv_html_mode = 'V'.
ELSEIF gv_html_mode = 'C'
    OR gt_detail IS NOT INITIAL.
  gv_html_mode = 'C'.
ELSEIF gv_p31_done = abap_true
    OR gv_p32_done = abap_true.
  gv_html_mode = 'S'.
ELSE.
  gv_html_mode = 'I'.
ENDIF.
```

### G. 테스트 실행과 중복 전기 방지
- 테스트 실행이면 실제 임률을 저장하지 않고 저장 예정 데이터만 팝업으로 보여 주며, 배부 전표 생성과 TEC 전환, 결산 단계 기록도 하지 않음
- 전기 전에 오더별로 같은 결산월의 기존 배부 전표가 있는지, 같은 FI 전표번호가 이미 있는지 확인하고 있으면 중단
- FI 헤더, CO 전표 라인, FI 라인을 INSERT하며 하나라도 실패하면 ROLLBACK, 모두 성공하면 COMMIT

```abap
IF pa_testrun = 'X'.
  MESSAGE '테스트 실행 상태에서는 생산오더 가공비 배부 전표를 생성하지 않습니다.' TYPE 'S' DISPLAY LIKE 'W'.
  RETURN.
ENDIF.
```

## 설계 판단 및 트러블슈팅
대표 사례 두 가지와 보조 사례 두 가지입니다.

### 사례 1. 생산오더 상태와 화면 결산 진행 단계의 불일치
- 문제: REL 오더는 가공비 배부가 끝나도 WIP 대상으로 남아야 해서 TEC로 바뀌지 않음. TEC 전환 여부를 중심으로 단계를 판단하면, 배부 전표가 이미 있는데도 앞 단계 버튼이 다시 활성화될 수 있음
- 처리: 결산월의 실제 배부 전표 존재 여부와 결산 단계 이력을 함께 확인해, TEC 전환 전이라도 배부 전표가 있으면 배부 완료 단계로 표시
- 처리: 화면 단계를 전역변수만으로 유지하지 않고, 재진입이나 조회 때 DB 처리 결과로 다시 계산

### 사례 2. ALV Field Catalog와 출력 테이블 구조 불일치
- 문제: 전표 미리보기(Header, 차변, 대변)와 전기 결과처럼 출력 구조가 다른 ALV가 Field Catalog를 함께 쓰면, 출력 테이블에 없는 필드를 참조해 덤프가 날 수 있음
- 처리: 전표 미리보기와 전기 결과 ALV의 Field Catalog를 별도 루틴으로 분리하고, 각 출력 테이블의 필드에 맞춰 구성

### 보조 사례 1. 테스트 실행 플래그 초기화와 고정
- 임률 산출 실행이나 저장 시점에 테스트 실행 여부를 고정하고, 고정된 뒤에는 체크박스를 바꿀 수 없게 표시
- 초기화와 새로고침에서는 테스트 실행 값과 고정 상태를 함께 지워, 이전 실행의 플래그가 남지 않게 함

### 보조 사례 2. HTML 검색조건 재렌더링 시 값 유지
- HTML 영역을 다시 그릴 때 기존 코스트센터, 활동유형 범위 조건(Range)의 값을 읽어 입력칸에 다시 넣어, 사용자가 고른 조건이 사라지지 않게 함

## 검증 및 결과
실제 실행 화면에서 확인한 내용과, 소스에서 확인한 처리를 구분해 정리했습니다.

### 실제 화면에서 확인한 내용
- 실제 임률: 2026년 6월, 버전 010 조건에서 CC_EBK01 WELDSH(가공/용접 노무)는 총 고정비 89,000,000, 총 변동비 88,000,000, 실제 총 공수 2,375시간으로 고정 단가 37,474, 변동 단가 37,053, 실제 단가 74,527입니다
- 이 화면에서 계획 단가 칸은 0으로 표시되어, 단가 차이가 실제 단가와 같게 나옵니다
- 가공비 배부: 생산오더 PROD10000145는 공정 0010 WELDSH 2,375시간 × 74,527 = 177,001,625처럼 활동유형별로 계산되어, 배부 금액 합계 1,434,901,925로 TEC / 가공비 배부 및 마감 완료 상태입니다
- 후속 처리: 처리 완료 후 진행 상태 5단계가 모두 완료(100%), 해당 오더 비고가 TEC 완료로 표시됩니다
- 2026년 5월 조회 화면에서 REL 오더는 생산중, 실적 확인 상태로 남아 있습니다

## 기여 및 산출물
CO 담당으로 실제 임률 산정과 생산오더 가공비 배부 프로그램을 설계하고 ABAP으로 개발했습니다. 소스 변경 이력 기준으로 2026년 4월 최초 개발 후 6월에 생산오더 마감 처리 기능을 추가했습니다.

### 주요 개발 영역
- Module Pool 단계형 화면과 HTML 검색조건, 진행 상태
- 실제 임률 산정과 계획 대비 비교
- 생산오더 가공비 배부, 전표 미리보기, 전기
- 생산오더 상태별 후속 처리와 결산 단계 기록
- 테스트 실행과 중복 전기 제어

### 연계 업무
제조간접비 배부(SAPMZC1CO0003)의 배부 결과 전표와 배부 이력을 읽어 실제 임률을 산정하고, 가공비 배부 이후 REL 오더는 다음 단계인 재공품(WIP) 계산으로 넘어갑니다.

### 배운 점
> 결산 프로그램에서는 숫자를 계산하는 것만큼 지금 어느 단계까지 처리되었는지를 정확히 아는 것이 중요했습니다. 오더 상태만이 아니라 실제로 만들어진 전표와 단계 이력을 기준으로 화면을 복원하고, 테스트 실행과 중복 전기를 구조적으로 막는 데 집중했습니다.
