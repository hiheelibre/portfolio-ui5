## 문제 정의 및 개발 배경
부서별 예산을 편성한 뒤 공통부서의 예산을 수혜 부서에 배부하지 않으면, 실제 비용(배부 후 금액)과 같은 기준으로 비교하기 어렵습니다. 예를 들어 전기세나 복리후생비는 공통부서가 예산을 갖고 있지만 실제로는 생산부서와 영업부서가 함께 쓰는 비용입니다.

태산자전거 프로젝트에서는 제조간접비 실제 배부(STEP 1)와 같은 배부 규칙과 통계지표를 예산에도 적용하도록 설계했습니다. 이를 통해 직접예산과 배부예산을 구분하고, 최종예산 = 직접예산 + 배부예산을 실적과 비교하는 흐름을 한 앱 안에서 처리했습니다.

## 업무 및 데이터 흐름
직접예산 편성 → 연간 예산 월 배분 → 부서간 예산 배부 → 배분과 배부 이력 확인 → BvA 리포트 조회 → 월별 드릴다운 순서로 진행됩니다. 화면은 예산 편성, 예산 배부와 이력, BvA 리포트의 탭 3개로 구성했습니다.

### 단계별 처리
| 단계 | 처리 내용 | 주요 데이터 |
| --- | --- | --- |
| 예산 편성 | 행 추가 또는 엑셀 업로드로 부서, 계정별 직접예산 등록 | ZTC1CO0022 예산 |
| 월 배분 | 연간 예산(기간 000)을 1~12월로 나눔, 월 합계가 연 예산과 같아야 저장 | ZTC1CO0022 예산 |
| 부서간 배부 | 실제 배부 규칙과 SKF로 수신부서 배부예산 생성 | 사이클 ZTC1CO0020, 세그먼트 ZTC1CO0021, 송수신 ZTC1CO0023, SKF ZTC1CO0030/0031 |
| 이력 | 배부 종류, 차대변, 문서번호, 처리 상태 기록 | ZTC1CO0038 배부 이력 |
| BvA | 최종예산과 실제 비용 비교, 집행률과 상태 판정 | 예산과 실적 결합 CDS |

### BvA 계산
최종예산 = 직접예산 + 배부예산

부서와 계정별로 최종예산, 실적, 차이, 집행률을 계산하고, 상태를 초과, 주의, 미집행, 무예산실적, 정상으로 판정합니다.

## 핵심 구현 내용
### A. Managed RAP 기반 데이터 처리
예산 테이블(ZTC1CO0022)을 기반으로 RAP 비즈니스 객체를 구성했습니다. 예산 편성 객체는 생성, 수정, 삭제를 지원하고, 배부 객체는 화면에서 직접 생성, 수정, 삭제할 수 없게 하고 Action만 열어 두었습니다. 연간 예산의 월별 저장은 static Action으로 정의했습니다.

```abap
define behavior for ZCDS_C1_CO_0031 alias Distribution
persistent table ztc1co0022
lock master
authorization master ( global )
{
  action distributeBudget parameter ZCDS_C1_CO_0037 result [1] $self;

  static action saveMonthlyDistribution parameter ZCDS_C1_CO_0055;
}
```

### B. Abstract Entity 기반 Action 파라미터
배부 버전, 예산 카테고리, 배부방식, 배부 기준기간을 Abstract Entity로 정의해 Action 파라미터로 받았습니다. 화면의 조회 조건을 그대로 넘기므로 Action 안에서 값을 하드코딩하지 않습니다.

```abap
define abstract entity ZCDS_C1_CO_0037
{
  DistVer    : abap.char(10);
  Category   : abap.char(10);
  DistMethod : abap.char(10);
  Poper      : abap.numc(3);
}
```

### C. 배부 금액 계산과 정합성
| 처리 | 내용 |
| --- | --- |
| 배부 규칙 조회 | 발신 코스트센터와 계정으로 사이클과 세그먼트를 찾고, 세그먼트의 통계지표로 수신부서 SKF 값 조회 |
| 배부금액 | SKF 비례는 원예산 × 수신 SKF ÷ SKF 합계, 균등은 원예산 ÷ 수신부서 수 |
| 단수 보정 | 원 단위 반올림 후 남은 차이를 수신처 한 곳에 더함 |
| 합계 검증 | 보정 후에도 수신 합계가 원예산과 다르면 오류로 중단 |
| 라인 생성 | 같은 문서번호에 발신부서 음수 라인과 수신부서 양수 라인 생성 |
| 이력 기록 | 이력 테이블에 예산 배부 종류(B)와 차대변 구분(H, S)으로 기록 |

```abap
lv_diff_amt = lv_org_amt - lv_sum_amt.

DESCRIBE TABLE lt_recv LINES lv_recv_cnt.

IF lv_recv_cnt > 0 AND lv_diff_amt <> 0.
  READ TABLE lt_recv ASSIGNING <ls_recv> INDEX lv_recv_cnt.
  IF sy-subrc = 0.
    <ls_recv>-final_amt = <ls_recv>-final_amt + lv_diff_amt.
    lv_sum_amt = lv_sum_amt + lv_diff_amt.
  ENDIF.
ENDIF.
```

### D. CDS 기반 BvA 리포트
직접예산, 배부예산, 실적을 결합하는 기반 CDS 위에 부서와 계정별 리포트, 전사 KPI 집계, 월별 드릴다운 CDS를 나눠 쌓았습니다. 기간 From/To는 파라미터 CDS로 전달하고, 상태 판정도 CDS에서 처리합니다. 화면에서는 KPI 카드와 상세표를 보여 주고, 부서명을 누르면 월별 드릴다운 팝업을 엽니다.

### E. 엑셀 업로드와 금액 파싱
SheetJS로 예산 템플릿 다운로드, 대량 업로드, 결과 내보내기를 구현했습니다. 금액 문자열은 공통 파싱 함수에서 콤마와 공백을 제거한 뒤 숫자로 바꿉니다.

## 설계 판단 및 트러블슈팅
설계 단계에서 미리 막은 위험과, 개발 중 실제로 고친 오류를 나눠 정리했습니다.

### 설계로 예방한 위험 1. 배부 후 전사 예산 총액 증가
- 위험: 수신부서 배부예산만 추가하면 발신부서 원예산과 함께 남아, 전사 예산 합계가 배부한 금액만큼 늘어남
- 설계: 배부 한 건을 발신부서 차감 라인(음수)과 수신부서 배부 라인(양수)으로 같은 문서번호에 묶어 생성
- 기준: 발신과 수신 배부금액의 합계가 0

### 설계로 예방한 위험 2. SKF 비례 배부의 단수 차이
- 위험: 배부율 계산과 반올림으로 수신부서 합계가 원예산과 달라질 수 있음
- 설계: 반올림 잔액을 수신처 한 곳에 더하고, 보정 후에도 맞지 않으면 실행을 중단
- 설계: 화면 미리보기에 배부금액, 조정금액, 최종 배부금액, 원예산과의 차이를 함께 보여 줘 실행 전에 확인

### 설계로 예방한 위험 3. 같은 예산의 중복 배부
- 위험: 같은 조건으로 다시 실행하면 배부예산이 중복 생성될 수 있고, 같은 이력 테이블을 쓰는 실제 비용 배부 이력과 섞일 수 있음
- 설계: 같은 조건의 배부예산이 이미 있으면 실행을 막고, 이력은 예산 배부 종류(B)로 구분해 실제 비용 배부(A)와 분리
- 설계: 배부예산 행은 예산 편성 탭에서 삭제할 수 없게 막음

### 실제로 고친 오류. 콤마가 포함된 금액 파싱
- 문제: 콤마가 들어간 금액 문자열을 parseFloat로 바로 바꾸면 첫 콤마 이후 금액이 무시됨
- 해결: 금액 파싱 함수를 따로 만들어 콤마와 공백을 제거한 뒤 숫자로 바꾸고, 미리보기 합계, 차이 계산, 엑셀 업로드 등 금액을 다루는 곳에서 모두 이 함수를 쓰도록 통일

## 검증 및 결과
### 통합테스트 시나리오의 기대값
설계 단계에서 작성한 통합테스트 시나리오에 배부 결과의 기대값을 먼저 적고 결과와 대조하는 방식으로 검증했습니다. 아래는 문서에 기록된 전기세 예산 배부 사례의 기대값입니다.

| 구분 | 배부금액 (원) |
| --- | --- |
| 발신부서 차감 | -60,000,000 |
| 수신부서 A | +30,000,000 |
| 수신부서 B | +20,000,000 |
| 수신부서 C | +10,000,000 |
| 배부 후 합계 | 0 |

### 실행 화면에서 확인한 내용
- 예산 편성: 회사 1000, 2026년 조건에서 연간과 월별 직접예산 3건이 조회되고, 연도별 편성 현황에 연도별 편성 규모와 편성 코스트센터 수가 표시됩니다
- 부서간 배부: 발신 코스트센터 CC_SUP02(생산지원팀, 계정 697000, 원예산 500)를 고르면 배부 기준 전력사용량(kW)에 따라 생산1팀 40.0%(200), 생산2팀 35.0%(175), 영업팀 25.0%(125)로 나뉘고, 배부 합계 500, 원예산과 차이 0이 실행 전에 표시됩니다
- BvA 리포트: 2026년 1~3월 조건에서 CC_HR01(인사팀)은 최종예산 10, 실적 0으로 미집행, CC_SUP01(지원팀)은 최종예산 60, 실적 2, 집행률 3.3%로 정상으로 판정됩니다
- 연간→월 배분: CC_SUP02의 연 예산 500을 균등 배분으로 나누면 1~11월은 41, 12월은 49로 잔액을 보정하고, 월 배분 합계 500과 연 예산의 차이 0을 저장 전에 보여 줍니다
- 배분/배부 이력: 배부를 실행한 뒤 이력에 처리유형 DIST, 배부문서 BD000001, 차대변 H, CC_SUP02 생산지원팀, 금액 500, 상태 완료가 기록됩니다
- 부서간 배부 미리보기 화면은 배부를 실행하기 전(미배부) 상태입니다

### 남은 제한사항
- 예산 행 없이 실적만 있는 경우는 BvA 상세표에 나타나지 않을 수 있음
- 화면에는 백엔드 조회 결과가 없거나 조회에 실패하면 시연용 데이터로 전환하는 장치가 있음
- 수신부서 양수 라인이 만들어진 예산 화면과 월별 드릴다운 팝업 캡처는 없음

## 기여 및 산출물
CO 담당으로 예산 편성, 배부, BvA 리포트 앱을 개발했습니다.

### 주요 개발 영역
