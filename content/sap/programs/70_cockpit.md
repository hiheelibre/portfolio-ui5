## 문제 정의 및 개발 배경
월말 CO 결산은 여러 프로그램을 업무 순서에 맞춰 실행해야 합니다. 그러나 프로그램을 하나씩 따로 실행하는 구조에서는 현재 완료된 단계와 다음에 해야 할 작업을 결산 담당자가 직접 기억하거나 확인해야 했습니다.

그래서 각 결산 프로그램이 저장한 처리 상태를 한 곳에서 조회하고, 다음 작업을 바로 알 수 있는 콕핏을 개발했습니다. 결산 프로그램 자체를 다시 만들지 않고, 프로그램들이 공통으로 쓰는 상태 데이터를 통해 연결하는 방식을 택했습니다.

## 업무 및 데이터 흐름
GUI 결산 프로그램 → 결산 상태 테이블 → CDS 기반 OData V2 조회 → ProcessFlow와 결산 이력 표 → 담당자 확인과 후속 실행 순서로 진행됩니다.

### 데이터 흐름도
| 구분 | 구성 요소 | 역할 |
| --- | --- | --- |
| 기록 | 제조간접비 배부(SAPMZC1CO0003) | 배부 완료 시 상태 테이블의 공통비 배부 단계를 완료(S)로 갱신 |
| 기록 | 실제 임률 산정 및 생산오더 가공비 배부(SAPMZC1CO0002) | 세부 단계 31~35를 처리할 때마다 상태 테이블에 완료(S) 기록 |
| 저장 | ZTC1CO0036 | 결산 단계별 처리 상태, 작업명, 처리일시, 처리자 |
| 저장 | ZTC1CO0039 | 회계연도와 결산 기간의 Open/Close 상태 |
| 조회 | CDS 뷰 + OData V2 (COCloseStepSet) | 회계연도와 결산월로 단계별 상태 조회 |
| 관리 | 기간 관리 OData V2 서비스 (PeriodSet) | 결산 기간 생성과 Open/Close 변경 |
| 표시 | ProcessFlow + 결산 이력 표 | 현재 상태와 다음 진행 단계, 전체 처리 이력 |

### 결산 단계 구성
| NO | 결산 단계 | 상태 연계 |
| --- | --- | --- |
| 01 | 데이터 수집 준비 | 기초 데이터 확인 |
| 02 | 비용 배부 확정 | 제조간접비 배부(SAPMZC1CO0003)가 완료 상태 기록 |
| 03 | 가공비 산정 | 실제 임률 산정 및 생산오더 가공비 배부(SAPMZC1CO0002)가 세부 단계 31~35(대상 오더 확인, 비용 전표 집계, 임률 산출 및 저장, 생산오더 배부, TEC 전환)마다 완료 상태 기록 |
| 04 | WIP 재공품 산정 | 재공품 산정 단계 |
| 05 | 월말 결산 마감 | 결산 마감 단계 |

ProcessFlow에는 결산 단계를 순서대로 노드로 놓고, 결산 이력 표에는 단계별 상태, 완료 일시, 완료자, 비고를 함께 보여 줍니다.

## 핵심 구현 내용
### A. GUI 결산 프로그램과 상태 데이터 연계
상태 테이블을 읽는 CDS 뷰에 OData 게시 어노테이션을 달아 OData V2 서비스로 노출했습니다. 화면은 회계연도와 결산월 필터로 이 엔터티셋을 조회합니다.

```abap
@OData.entitySet.name: 'COCloseStepSet'
@OData.publish: true

define view ZCDS_C1_CO_0002_DDL
  as select
        key kokrs   as CoArea,
        key gjahr   as FiscalYear,
        key poper   as FiscalMonth,
        key step    as CloseStep,
        key work_nm as WorkProcessNM,
            status  as Status,
            pc_date as ProcessOn,
            ernam   as CreatedBy,
            erdat   as CreatedOn,
            erzet   as CreatedTime
      from ztc1co0036;
```

### B. SAPUI5 ProcessFlow 상태 변환
조회 결과를 단계 순서대로 정렬한 뒤 상태 코드에 따라 노드 상태를 정했습니다.

| 상태 테이블 값 | 노드 상태 | 표시 |
| --- | --- | --- |
| S | Positive | 완료 |
| E | Negative | 오류 |
| 그 외, 완료되지 않은 첫 단계 | Critical | 진행 필요 (다음 진행 단계로 강조) |
| 그 외, 이후 단계 | Neutral | 대기 |

### C. 미실행 단계와 최신 상태 처리
아직 실행하지 않은 단계는 DB에 기록이 없으므로, 화면에 정의한 단계 마스터와 조회 결과를 병합해 기록이 없는 단계를 가상 행으로 채웠습니다. 같은 단계의 처리 이력이 여러 건이면 처리일시(없으면 생성일자와 시간)가 가장 최근인 기록으로 현재 상태를 판단하고, 전체 이력은 결산 이력 표에서 따로 보여 줍니다.

### D. 기간 관리와 WebGUI 연계
결산 기간은 별도의 OData V2 서비스로 생성하고 Open/Close 상태를 변경합니다. 화면을 열면 Open 상태인 기간 중 가장 최근 기간을 찾아 조회합니다. 단계 노드에서는 관련 GUI 트랜잭션을 WebGUI 주소로 여는 기능을 구성했지만, 단계별 트랜잭션 매핑의 정확성은 검증하지 못했습니다.

## 설계 판단 및 트러블슈팅
### 사례 1. 결산월 형식 불일치로 조회 결과 누락
- 문제: 결산월이 3, 03, 003처럼 서로 다른 형식으로 전달되어, 형식이 다르면 OData 조회 결과가 비어 보임
- 해결: 선택한 결산월로 형식 후보(3, 03, 003, 원래 값)를 만들고, 결과가 나올 때까지 후보를 차례로 조회
- 해결: 기간 선택 콤보의 선택값도 같은 후보 순서로 맞춰, 조회 결과와 선택 표시가 어긋나지 않게 함

### 사례 2. 미실행 결산 단계가 화면에서 사라짐
- 문제: 아직 실행하지 않은 단계는 DB 레코드가 없어 ProcessFlow에 나타나지 않고, 다음에 무엇을 해야 하는지 보이지 않음
- 해결: 단계 마스터와 조회 결과를 병합해 미실행 단계를 가상 행으로 표시하고, 완료되지 않은 첫 단계를 진행 필요로 강조

### 보조 사례. 같은 단계의 이력이 여러 건일 때
- 문제: 같은 단계를 다시 실행하면 이력이 여러 건 쌓여, 과거 기록이 현재 상태를 덮을 수 있음
- 해결: 단계별로 처리일시가 가장 최근인 기록만 골라 현재 상태로 쓰고, 전체 이력은 결산 이력 표에 남김

## 기여 및 산출물

- 결산 상태 CDS와 OData V2 조회

### 배운 점
> 여러 프로그램을 한 화면으로 묶을 때 프로그램을 직접 합치기보다, 공통 상태 데이터를 약속으로 두는 편이 각 프로그램을 덜 건드리고 연결할 수 있다는 것을 배웠습니다. 기록이 없는 단계와 여러 번 실행한 단계처럼 데이터에 드러나지 않는 상태를 화면에서 어떻게 보여 줄지 정하는 일이 핵심이었습니다.
